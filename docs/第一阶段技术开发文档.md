# 第一阶段技术开发文档｜本地双栏与版本闭环

> 配套文档：《Prompt Studio PRD V0.1》《AI Agent 产品 Vibe Coding 通用技术栈手册 V2.1》《技术适配声明》。本文档只覆盖第一阶段。

## 一、阶段目标

- 交付范围：完成“编辑当前工作稿 → 建立手动候选 → 逐段接受或拒绝 → 自动保存 → 保存正式版本 → 调回历史对比”的最小闭环。
- 阶段产物：可构建的 Swift Package、SwiftUI 工作台、SQLite schema、核心检查程序、启动与验收说明。
- 验收标准：默认栏目正确；当前版本身份不随位置变化；只接受目标栏目；工作稿和候选重启可恢复；正式版本不可被后续修改覆盖。
- 明确不做：DeepSeek、SSE、Keychain、设置窗口、导入导出、项目列表与搜索、备份、Diff、DMG。
- 主链路：新建默认工作区 → 输入工作稿 → 创建候选 → 部分接受 → 保存 V1 → 修改工作稿 → 用 V1 对比。

## 二、技术适配摘要

- 本阶段采用 SwiftUI、AppKit 剪贴板、Swift Package Manager、系统 SQLite3。
- 按需启用关系型持久化和最小真实界面。
- 不采用通用手册的 Python/FastAPI 默认项，原因是 PRD 明确为无后端的本地原生应用。
- 开发路径为纵向切片，因为左右对比和人工逐段处理是产品核心能力。

## 三、技术栈与模型

- Swift 6 工具链，源码使用 Swift 5 语言模式降低并发迁移噪声。
- SwiftUI 负责窗口和工作台；AppKit 只负责 `NSPasteboard`。
- SQLite3 负责工作稿、候选和版本历史。
- 本阶段不调用模型，不引入 DeepSeek 配置。

## 四、环境与配置

- 包入口：`Package.swift`。
- 默认数据库：`~/Library/Application Support/Prompt Iteration Assistant/prompt-iteration.db`。
- 测试或调试可使用 `--db <path>`；也支持 `PROMPT_ITERATION_DB`。
- 当前环境：官方 Command Line Tools；Swift 6.3.3。项目不依赖完整 Xcode。

## 六、数据、资产与状态

- `projects`：项目 ID、名称、当前正式版本号和时间。
- `draft_sections`：当前工作稿的稳定栏目 ID、名称、正文和顺序。
- `versions` / `version_sections`：不可变正式版本及完整栏目快照。
- `comparisons` / `comparison_sections`：当前对比来源、来源版本、栏目正文和处理状态。
- schema 版本：SQLite `user_version = 1`。
- 写入方式：每次业务修改使用 `BEGIN IMMEDIATE` 事务；SQLite WAL；忙等待上限 10 秒。
- 候选状态：`pending → accepted/rejected`；用户编辑候选后为 `user_modified`，之后仍可接受或拒绝。
- 删除栏目需要界面二次确认；历史版本不受删除影响。

## 七、自动化入口设计

本地原生应用不提供 HTTP API。`PromptIterationCore` 是独立业务模块，`PromptIterationCoreChecks` 是可脱离 UI 执行的等价自动化入口。

业务操作包括：

- 创建或恢复工作区。
- 保存完整工作稿。
- 保存、恢复或清除当前对比快照。
- 对指定稳定栏目 ID 执行应用或拒绝。
- 生成连续编号的正式版本并读取历史快照。

错误统一映射为 `validation`、`notFound`、`database`，用户界面不显示 SQLite 堆栈。

## 八、Prompt 设计

本阶段没有模型 Prompt。手动候选是临时验收输入方式，后续 DeepSeek 结构化结果将写入同一对比数据契约。

## 九、纵向切片界面

- 顶部：Prompt 名称、版本状态、左右交换、完整复制和保存新版本。
- 当前版本面板：始终高亮、可编辑，支持栏目新增、删除、改名和排序。
- 对比面板：空白、手动候选或历史版本；手动候选可编辑，历史版本只读。
- 栏目操作：接受/应用、拒绝和复制。
- 底部：自动保存状态和本地数据库位置。

## 十、测试要求

自动化核心检查：

- 默认 12 栏目及工作稿重启恢复。
- 只应用目标栏目，拒绝不改变当前工作稿。
- 候选内容和处理状态持久化。
- 正式版本号连续，历史快照不被新工作稿覆盖。

本阶段无模型调用，真实模型冒烟不适用。已运行 `swift run PromptIterationCoreChecks`，并启动 UI 进入手工验收。

## 十一、验收清单

- [ ] 首次启动后看到 12 个默认栏目。
- [ ] 修改栏目正文，重启应用后内容仍在。
- [ ] 新建手动候选并填写两个栏目。
- [ ] 接受第一个栏目、拒绝第二个栏目，只有第一个当前正文变化。
- [ ] 交换左右后，当前编辑版本仍保持蓝色高亮并可输入。
- [ ] 保存正式版本后显示 V1，再次保存显示 V2。
- [ ] 把 V1 调入对比区，其内容只读；应用一段不会改写 V1。
- [ ] 删除栏目时出现确认；删除后已保存历史版本仍保留该栏目。
- [ ] 完整复制结果跳过空栏目，不包含界面栏目名。

## 十二、风险与待确认项

- 受限沙箱若禁止 SwiftPM 写入用户级模块缓存，可能出现误导性的 SDK 报错；在普通终端或允许缓存写入的环境中构建已通过。
- 每次编辑直接写 SQLite 适用于单用户小规模 Prompt；只有性能测试出现卡顿时才增加防抖。
- 第一阶段只支持最近使用的一个项目；多项目管理由后续 Prompt 管理阶段实现。
- 最低 macOS 版本待确认，临时值为 macOS 13。

## 十三、交接给下一阶段

下一阶段可直接复用稳定栏目 ID、工作稿快照、候选状态、不可变版本 schema 和双栏界面。接入 DeepSeek 时只需新增 Keychain、模型服务、SSE 解析和结构化候选写入，不需要改写已验证的逐段应用逻辑。
