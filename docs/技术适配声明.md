# 技术适配声明

## 1. 产品形态判断

- 产品类型与核心任务：单用户、本地优先的原生 macOS Prompt 工作台，用双栏和逐段决策管理 Prompt 迭代。
- 核心交互：结构化编辑、分段确认、历史版本对比；交互本身决定产品是否可用。
- 开发路径：纵向切片。第一阶段同时实现最小本地数据层、真实 SwiftUI 工作台和自动化核心检查。
- 当前阶段范围：默认栏目、当前工作稿、手动候选或历史对比、左右交换、逐段接受/拒绝、自动保存、正式版本快照。

## 2. 采用的默认方案

- Git：在新工程目录独立初始化，避免参考项目和产品文档被开发产物污染。
- Swift Package Manager：符合 PRD 的 VS Code 开发条件，也沿用参考项目结构。
- SwiftUI + AppKit：SwiftUI 构建原生界面，AppKit 仅用于系统剪贴板。
- 系统 SQLite3：项目存在工作稿、栏目、候选和版本等关系数据，使用事务保证正式版本不可变。
- 无第三方运行时依赖：第一阶段全部使用系统框架。
- 无依赖核心检查程序：本地原生项目以可独立执行的自动化入口替代 Web API。

## 3. 触发的按需模块

- SQLite：由多实体关系、不可变历史和重启恢复触发，本阶段引入。
- 最小真实界面：由双栏编辑、左右交换和人工逐段确认触发，本阶段引入并作为正式产品切片继续演化。
- AI SSE：PRD 要求，但第一阶段不调用模型，因此暂不引入。
- Keychain：到 DeepSeek 设置与调用阶段再从 `DeepSeekMonitor` 复用。

## 4. 偏离或暂缓的默认方案

- Python/FastAPI/Pydantic/pytest：替换为 Swift、SwiftUI、SQLite3 和 Swift 可执行检查程序。原因是 PRD 明确要求纯本地原生 Mac 应用、无自建后端；引入本地 Web 后端会增加进程、端口和密钥边界。
- Web 前端：不采用。目标终端已明确为 Apple Silicon macOS 原生应用。
- SQLAlchemy/Alembic：不采用。系统 SQLite 通过显式 schema 与 `user_version = 1` 管理第一阶段结构，避免引入不适用的 Python 依赖。
- API：不创建。核心业务位于独立 Swift library，并通过 `PromptIterationCoreChecks` 独立验证；后续模型请求仍直接由原生客户端经受控服务层发出。
- DeepSeek、导入导出、完整 Prompt 管理和分发：暂缓到后续阶段，避免在核心交互通过前扩大范围。

## 5. 强制底线检查

- 密钥与隐私：通过。本阶段无密钥、无网络请求，Prompt 只进入本地 SQLite。
- 数据与任务可恢复：已实现。工作稿、候选内容、处理状态和正式版本均持久化。
- 输入输出校验：已实现栏目 ID 唯一、名称非空、项目存在性和受控状态值校验。
- 错误与日志边界：已实现本地化用户错误；不记录完整 Prompt 或秘密。
- 测试与真实模型验收：4 条核心自动化检查已全部通过；本阶段无模型调用，不要求真实模型冒烟。

## 6. 需要产品经理决定的问题

- 最低支持 macOS 版本仍需最终确认；第一阶段临时采用 macOS 13，与 `prompt-version-manager` 参考项目一致，不阻塞代码推进。
